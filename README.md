# Agent Tool Router

项目 B 的独立实现，工作名尚未查重。不绑定 REA 或某一家模型；目标是在 Agent 调用工具前，提供可拒选、可回退、可验证的工具推荐。

**当前阶段：目录快照、词法基线、可插拔评分编排已实现。内置演示全部离线，尚未接入 MCP、REA 或 Jev，不执行真实工具。**

## 本地使用

需要 Node.js 24 与 npm。

```sh
npm ci --ignore-scripts
npm run check
npm run demo
npm run demo:provider
```

demo 使用人工工具描述和模拟状态，展示：推荐查看差异、过滤不在白名单的提交工具、报告缺少仓库、无匹配时拒选。它不读取真实仓库或文件，不是模型效果 benchmark。

demo:provider 使用模拟评分器，展示选择、非法返回、显式回退、超时和取消，不请求远程模型。routeWithProvider 允许应用显式传入自己的评分器；该实现的网络访问和数据处理由应用负责。

## 已实现与未实现

| 能力                                               | 状态                       |
| -------------------------------------------------- | -------------------------- |
| 工具命名空间、输入校验、深拷贝冻结、稳定 SHA-256   | 已实现                     |
| 简单中英文词法召回、稳定排序、并列拒选             | 已实现，不具备语义理解     |
| 显式允许名单、ready/missing/unknown 状态、版本回执 | 已实现，来自可信应用配置   |
| DecisionProvider 异步编排                          | 已实现，可注入模拟评分器   |
| 评分器输出结构与候选成员校验                       | 已实现独立解析器           |
| 置信度门限、等待超时/取消、显式词法回退            | 已实现，不承诺强停后台任务 |
| Jev HTTP 适配与真实模型评测                        | 尚未实现                   |
| MCP 转发、真实工具执行、参数级授权、REA 适配       | 尚未实现                   |

词法匹配只是基线，可能漏掉同义表达，也可能误选表面相关的工具。selected 始终是建议，不是执行许可；调用方不能拿它跳过权限检查。正式执行前还需要实时状态和参数校验。

## 核心原则

- 模型推荐不等于用户授权。策略、参数验证与执行前检查独立于评分器。
- 没有合适工具、状态未知、模型失败均应显式返回，不强行选择第一名。
- 缺少前置资源不等于永远不可用；需要前置步骤的工具与立即可用工具分开。
- Jev 是后续可选的决策提供者，不是不可替换的产品基础。
- 不宣称完整 Agent、通用沙箱或已经测得成本收益。
