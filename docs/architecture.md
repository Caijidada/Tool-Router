# 架构决策：先做可测内核，再接模型与协议

状态：实施起点；2026-10-23。

实施进度：S0–S2 已完成本地验证。下面 DecisionProvider 调用、模型输出验证、超时/取消和真实适配器属于 S3 及后续设计目标，目前仅定义提供者接口，不能当作已实现能力。

## 1. 分层

1. Catalog：校验工具描述、命名空间和版本；生成确定性的目录摘要。
2. Policy / State：使用调用方可信配置判断工具是否允许、前置资源是否满足。
3. Retrieval：确定性词法基线，召回有限候选；明确这不是 BM25 或语义理解。
4. DecisionProvider：统一接口，允许词法选择、Jev Choice 和测试用假实现；输出可以拒选。
5. Router：编排候选、校验决策结果、处理不确定性、超时和取消。
6. Adapters（后续）：MCP 连接与执行；REA 专属 Evidence 状态不进入通用内核。

当前 Router 只返回建议，不生成授权令牌，也不执行工具。执行器必须重新校验实时状态与实际参数。

## 2. 边界与非目标

- 第一阶段单进程、单用户、本地 CLI；不建 Web 控制台、向量数据库或分布式服务。
- 不把外部工具 annotations 当成可信安全策略；默认不允许未配置的工具。
- 不把 Schema 格式正确当成领域参数正确，更不当成权限已批准。
- 不把缺少前置资源的工具交给模型直接执行；返回 needs_prerequisites 等结构化信息。
- 不能因为模型出错就自动尝试更高风险工具；回退仅影响推荐，不扩大允许范围。
- 说明文本是数据，不是可以改变本地策略的指令。

## 3. 数据与验证

工具身份采用 serverId + toolName，避免不同 MCP 服务的同名工具碰撞。输入 Schema 保留为 JSON，但内核第一步仅验证其 JSON 结构，不声称实现完整 JSON Schema 校验器。

目录摘要必须对对象键与工具排列稳定，对真正的描述、Schema 和身份变化敏感。数组顺序不随意改写。测试同时覆盖重复身份、非法输入、修改原对象、未知状态和空候选。

评分器输出只接受当前候选中的身份。输出未知工具、非法置信度或无效数据时返回错误/拒选，不能放行。置信度是决策信号，不是安全保证；阈值需独立留出集验证。

## 4. Jev 接入约束（尚未实现）

先实现 Choice + 明确的 none 选项，再考虑 Score / Noul。固定具体模型版本并记录实际返回版本；调用必须有总超时、取消、响应校验和可见失败。没有密钥时离线模式应完整可用。

只发送任务、必要的候选元数据和明确允许的状态。默认不发送源码、真实路径、凭据或完整历史。接入不等于授权付费运行，真实评测前单独配置密钥与预算。

参考：[Jev API](https://docs.typesafe.ai/api/system-one)、[模型版本](https://docs.typesafe.ai/models)、[已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 5. 评测原则

先测试确定性正确性，再做模型评测。后续对比原 Agent 直连、静态小工具集合、词法基线与 Jev，统一输入与预算；记录成功率、拒选、误选、回退、总延迟与总费用。假的模型响应只用于协议与异常测试，不算模型效果数据。
